# Agent instructions

## Project continuity

- Read `PROJECT_CONTINUITY.md` before making changes, then the focused guides it links.
- Check the current branch, remote history, open work and local changes. Treat dated notes as evidence of a past check, not proof of current deployment or account settings.
- Keep the continuity file current after meaningful code, configuration, deployment or project decisions and before handing work back. Record what changed, verification performed, unresolved issues and the next concrete step.
- Preserve existing decisions and detailed history. Link long records instead of replacing them with a lossy summary; distinguish implemented, deployed and user-accepted behavior.
- Never put credentials, private keys, session links, customer records or private attachments in continuity notes. Record secret names and storage locations only.
- The continuity record supports recovery when a chat is unavailable. It does not replace current user instructions or extend permission to unrelated actions.
